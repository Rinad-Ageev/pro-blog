# RRA founder journal

[Русский](README.ru.md) · [简体中文](README.zh-CN.md)

I’m RRA. Here I tell the story of developing my own ERP, specialized workspaces, a marketplace, and AI agents. I manage the development and describe my contribution separately from the work of others.

I wanted to cover gaps in the warehouse, where manual controls were no longer enough. A solution built with GPT’s help began developing into an ERP. The [first entry](posts/001-why-my-own-erp.en.md) tells that story based on my recollections. The exact starting date has not been reconstructed; implementation is still underway. Separately documented development milestones follow below.

## Documented milestones

These are event dates in 2026, not journal publication dates. The chronology draws on saved reports and evidence. No fresh check of the operational services was performed for this journal; continuous operation between milestones has not been confirmed. The earliest milestone found does not establish when development began.

| Event date | What was confirmed and what remained open |
|---|---|
| 22 August | A local warehouse core package was assembled for testing with training data. It had no persistent storage or real integrations; physical acceptance was not confirmed. |
| 18 September | An audit of the marketplace prototype confirmed catalog elements and local scenarios. Full trading and an operational release had not yet been confirmed. |
| 20 September | One client prototype prepared local cargo and processing request drafts, saved only in the current session. Real integrations were not connected at this stage. |
| 25 September | The warehouse ERP received a server deployment with installation checks. Physical printing, scanning, and an end-to-end operational order remained open. |
| 27 September | The procurement workspace received a fix for session timing. Checks stopped treating expired access as a valid session; this change did not enable connections to the ERP or external services. |
| 28 September | The client workspace was deployed as a closed owner pilot. Real data sources, client permissions, and exchange with the ERP still required verification. |
| 29 September | According to a dated report, the logistics workspace received a domestic transport module with vehicles, drivers, and manual requests. Operation after sign-in and external connections remained a separate verification stage. |
| 29 September | Action history and built-in guidance were added to the procurement workspace. Importing information was kept separate from verifying a supplier, and an assistant’s action from an employee’s action. This release did not enable ERP or AI connections. |
| 2 October | The logistics workspace began showing the reason for a PDF preparation failure in the card. Unverified data continued to block the document. Acceptance of an operational trip remained open. |
| 4 October | Saved evidence confirms the server installation of warehouse ERP R46A. Receiving, 3D pallet placement, and loading modes were improved. Physical acceptance and real connections between workspaces remain open. |
| 4 October | Client release R6P5 received an updated interface and 2D/3D planner code as installed code in a closed owner pilot. Real catalogs, client permissions, and actual warehouse operations were not activated. |
| 4 October | A composition of marketplace modules passed bounded independent QA in an isolated environment. The main screens are not connected; user operation and full trading require separate acceptance. |
